# End-to-End Demo Runbook: Fixed Deposit failure → Dynatrace → Devin PR

This walks you through the full event-driven demo:

```
Fixed Deposit create  →  HTTP 500 (seeded defect)  →  Dynatrace problem
      →  custom webhook  →  this relay  →  Devin session  →  Devin opens a fix PR (not merged)
```

There are two layers you can demo independently:

- **Relay only** (fastest, no banking stack, no Dynatrace) — great for rehearsing
  the Dynatrace-payload → Devin-session step. See [Track A](#track-a--relay-only-5-minutes).
- **Full stack** (real Fineract returning a real 500, real Dynatrace detection) —
  see [Track B](#track-b--full-stack).

---

## Prerequisites

| Tool | Version | Notes |
| --- | --- | --- |
| Node.js | ≥ 18 | for the relay |
| Docker + Docker Compose | any recent | runs Fineract's MySQL (Track B) |
| Java (JDK) | **11** | Fineract build/run (Track B). This branch uses the Gradle 6.9 wrapper. |
| ngrok | any | exposes the relay to Dynatrace (Track B) |
| A Devin API token | — | to actually create sessions (both tracks, live mode) |
| A Dynatrace tenant | trial is fine | Track B only |

## Track A — Relay only (5 minutes)

```bash
cd demo/dynatrace-devin-relay
npm install

# Dry run: parse the sample Dynatrace payload + print the Devin prompt, no API call.
npm run dry-run
# In another terminal:
curl -X POST http://localhost:3000/replay | jq

# Or fully offline, no server:
npm run replay
```

To actually create a Devin session, provide credentials and drop `DRY_RUN`:

```bash
cp .env.example .env
# edit .env: set DEVIN_API_TOKEN=<your token>, leave DRY_RUN=0
npm run start:env
curl -X POST http://localhost:3000/replay | jq   # response includes session_id + url
```

That's the whole relay→Devin path. Track B just replaces the canned payload with
a real Dynatrace problem generated by a real 500.

### B3. Trigger the failure

```bash
cd demo/dynatrace-devin-relay
./scripts/trigger-fd-500.sh            # one submission
COUNT=10 ./scripts/trigger-fd-500.sh   # ten, to push the failure rate up for Dynatrace
```

The script creates a client + a fixed-deposit product, then submits a fixed
deposit. Each submission returns **HTTP 500** because of the seeded
`NullPointerException` in
`DepositApplicationProcessWritePlatformServiceJpaRepositoryImpl.submitFDApplication`.

Verify in the Fineract log you see:

```
java.lang.NullPointerException
    at ...DepositApplicationProcessWritePlatformServiceJpaRepositoryImpl.submitFDApplication(...)
```

### B4. Set up Dynatrace (trial account)

1. **Create a trial tenant.** Sign up at <https://www.dynatrace.com/signup/>
   (15-day free SaaS trial). You'll get a tenant URL like
   `https://<env-id>.live.dynatrace.com`.
2. **Deploy OneAgent** on the host running Fineract so Dynatrace can see the
   service and its failures:
   - In Dynatrace: **Deploy Dynatrace / Start installation → Linux** (or your OS),
     copy the one-line installer command, run it on the Fineract host as root.
   - OneAgent auto-discovers the JVM and starts monitoring the
     `fineract-provider` service and its HTTP requests within a few minutes.
3. **Generate load / failures** by running `trigger-fd-500.sh` a number of times
   (`COUNT=20`). Dynatrace needs a few minutes and a high enough failure rate to
   open a problem. You can also lower the sensitivity via a custom anomaly-
   detection rule for faster demos.
4. Confirm a **Problem** opens (Dynatrace → **Problems**) describing the
   increased failure rate / exception on the savingsaccounts (Fixed Deposit)
   endpoint.

> If live detection is too slow for a live audience, skip straight to the relay's
> `/replay` endpoint (Track A) — it fires a representative payload through the
> exact same code path.

### B5. Expose the relay and wire the webhook

```bash
cd demo/dynatrace-devin-relay
cp .env.example .env          # set DEVIN_API_TOKEN, DRY_RUN=0
npm run start:env             # terminal 1
ngrok http 3000               # terminal 2 → note the https URL
```

In Dynatrace: **Settings Classic → Integration → Problem notifications →
Add notification → Custom integration**:

- **Webhook URL**: `https://<your-ngrok>.ngrok-free.app/dynatrace-hook`
- **Custom payload** (JSON):

  ```json
  {
    "ProblemID": "{ProblemID}",
    "ProblemTitle": "{ProblemTitle}",
    "ProblemImpact": "{ProblemImpact}",
    "ProblemSeverity": "{ProblemSeverity}",
    "State": "{State}",
    "ImpactedEntityNames": "{ImpactedEntityNames}",
    "ProblemURL": "{ProblemURL}",
    "ProblemDetailsText": "{ProblemDetailsText}"
  }
  ```

- Click **Send test notification** — you should see the relay log the parsed
  problem and (in live mode) return a Devin `session_id` + `url`.
- **Save.**

### B6. Watch Devin open the PR

When a problem fires (or you send the test notification), the relay:

1. parses the Dynatrace payload,
2. builds a prompt (repo URL, the Fixed Deposit endpoint, and the root-cause
   context),
3. calls `POST https://api.devin.ai/v1/sessions`, and
4. returns the new session's `session_id` and `url`.

Open that URL to watch Devin diagnose the duplicate-notification failure and
open a pull request with the fix. **The prompt explicitly tells Devin to open the
PR only and NOT merge it.**

## The seeded defect (what Devin is expected to fix)

In `submitFDApplication`, the legitimate `FIXED_DEPOSIT_ACCOUNT_CREATE` business
event is emitted once. A **duplicate** emission block was added that first
dereferences a deliberately-null reference, throwing an NPE on every valid
submission. The correct fix is to **remove the entire duplicate block**, leaving
the single original notification. See the clearly-marked
`SEEDED DEMO DEFECT` comment in
`fineract-provider/.../DepositApplicationProcessWritePlatformServiceJpaRepositoryImpl.java`.

## Reset between runs

- Re-running `trigger-fd-500.sh` always creates fresh clients/products, so it's
  safe to run repeatedly.
- To fully reset Fineract's data: `docker compose down -v && docker compose up -d fineractmysql`
  (this drops the MySQL volume; Flyway re-initializes on the next `bootRun`).

## Security note (demo scope)

The relay endpoints are **unauthenticated** and log the full payload/prompt for
visibility. That's intentional for a local ngrok demo. For anything beyond a
demo, add a shared-secret header check, rate limiting, and payload redaction, and
return only `status` + `session_id`.
